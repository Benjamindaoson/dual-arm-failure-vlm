\begin{abstract}
A robot execution critic can obey its output contract without recognizing when an assembly fails. We examine that distinction in causal REBOOT precision-assembly windows with a Qwen2.5-VL-3B critic. Supervised fine-tuning (SFT) makes every final-test response valid JSON, but its three state-only seeds identify substantially fewer failure windows than a fenced-output Base model. Base itself is not a useful detector: it predicts failure almost everywhere, including every nominal window. A separate validation contrast shows that asking for phase and failure mode as well as state can change the failure readout even before training. These are small, single-task, internally exposed diagnostics, not independent replication or a production-safety result.
\end{abstract}
\keywords{robot failure monitoring, multimodal critics, evaluation reliability}

\section{Introduction}
In contact-rich assembly, an execution monitor is useful only if its answer is both consumable by a downstream system and informative about the current state. These are different properties. A valid JSON object can say \emph{nominal} during a failure; an otherwise useful answer can be rejected because it is enclosed in a Markdown fence. We call the first property \emph{interface compliance} and the second \emph{failure awareness}. The question here is whether post-training moves them together.

REBOOT provides bimanual precision-assembly trajectories with phase, failure, and recovery annotations~\citep{reboot2026}. We use its cylinder-install sample to study a Qwen2.5-VL-3B~\citep{qwen2025} execution critic, not a recovery policy. The contribution is a paired diagnostic protocol that keeps strict deployable scoring separate from a narrowly normalized semantic readout and reports failure recall together with precision, nominal false alarms, and prediction distribution. This framing is consistent with broader concerns about fine-tuned VLM failure judges~\citep{failbench2026}, but the result is specific to our data, prompts, and adapters. Here \emph{collapse} means suppression or degeneration of this measured failure readout, not global model degradation.

\section{Setup and evidence boundaries}
\paragraph{Data and splits.}
The locally audited REBOOT sample contains 60 episodes; seven are quarantined for annotation/frame inconsistencies, leaving 53 usable episodes. We sample four causal timestamps over the preceding two seconds from a two-camera view, never reading beyond the anchor frame. V1 partitions complete episodes into train, validation, and diagnostic test. V2 development screens camera, supervision density, trace input, and output schema on development episodes. The final C2 sparse-visual refit uses a frozen six-episode Tier-B test with 54 windows, balanced across nominal, failure, and recovery. Those six episodes are disjoint from the \emph{final refit's} train and validation sets, but all six appeared in an earlier development training pool. The exposure ledger therefore classifies Tier B as \emph{internal evidence}; no same-task episode in this 60-episode sample is untouched.

\paragraph{Scoring.}
Strict scoring requires a bare valid JSON object with the exact required keys and labels. Semantic scoring may remove whitespace and at most one complete outer unlabeled or lowercase-\texttt{json} fence; it performs no JSON repair, field extraction, or label remapping. The same task evaluator then scores both forms. We report strict validity, semantic state Macro-F1, failure recall and precision, nominal-window false-alarm rate (N-FA), recovery recall, and predicted-state counts. N-FA is not an onset-relative early-warning measure. Uncertainty is computed by resampling whole episodes, with the identical paired episode draw for two models; correlated windows are never resampled independently.

\section{Discovery and controlled diagnostics}
The retrospective V1 diagnostic exposed a format/content mismatch: outer fences made Base responses fail strict parsing, whereas a narrowly normalized semantic diagnostic could recover their state content. The later V1 SFT and historical RL runs do not form a matched causal intervention, so we use them only to motivate the V2 controls.

On the five-episode development-validation set, the chosen high-plus-left-wrist C2 view attains high failure recall under a state-only output, but also makes many nominal false alarms and fails to recognize recovery. Thus the camera-selection rule (failure recall, then state Macro-F1) selected an observable signal, not a deployable detector. Denser supervision changed class balance as well as temporal density, so its inferior validation Macro-F1 cannot isolate a temporal mechanism. A separately trained Trace-Text adapter improved Macro-F1 while missing failures that the visual-only adapter recognized; it was not selected by the failure-first rule.

The most direct formulation contrast uses the same C2 images and validation IDs. With a state-only prompt, both Base and its state-only SFT recognize all failure windows. With a phase/state/failure-mode prompt, both corresponding full-schema conditions recognize none. The \emph{Base} contrast holds checkpoint and image input fixed and implicates prompt/output formulation before training; the SFT contrast additionally changes targets and adapter. Neither contrast identifies whether phase, failure mode, instruction length, or label coupling is responsible. A decomposition would require a new, pre-specified experiment and is not claimed here.

\section{Internal Tier-B refit: compliance is not awareness}
Table~\ref{tab:final} is regenerated from six receipt-verified prediction files, with identical final sample IDs. State-only Base has zero strict JSON validity but recognizes all failure windows after outer-fence normalization. It also marks every nominal window as failure and produces failure in 53 of 54 responses: perfect failure recall here is a high-alarm failure mode, not strong monitoring. All three SFT seeds produce bare valid JSON, but their failure sensitivity and false-alarm rates differ. The full-schema Base and SFT both miss every failure window. The full-schema SFT's improvement in protocol validity and some non-failure state discrimination therefore is not an improvement in failure awareness.

\section{Limitations and conclusion}
The finding supported here is that protocol compliance and semantic failure recognition can move in different directions for this recipe. It is \emph{not} that Base is a good detector, that SFT generally destroys robot awareness, or that the schema experiment proves an internal representation mechanism. There are only six internally exposed final episodes from one cylinder-install task. Annotation-defined failure intervals are not independent human judgments of visual observability. Compatible second tasks are listed in public REBOOT metadata, but the required label-grounded observations and compute were not available for a frozen replication in this study; cross-task generalization remains unmeasured.

A deterministic V2 reward verifier passed its tests, but the pre-test validation gate found no full-schema SFT outcome gain over Base and returned \texttt{REVISIT\_REPRESENTATION\_OR\_SUPERVISION}. No V2 GRPO or GSPO was run; state-gated reward remains an untested intervention. Historical V1 RL outputs do not establish a controlled reward comparison. The practical lesson is methodological: evaluate a robot critic's interface, failure sensitivity, and false-alarm behavior separately before treating a format improvement as a safety-relevant gain.
