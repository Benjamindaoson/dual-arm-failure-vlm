\begin{abstract}
A robot execution critic can appear to improve or degrade depending on an output and evaluation protocol often treated as an implementation detail. We use one precision-assembly task and a Qwen2.5-VL-3B critic as a small model organism for this evaluation substrate: output schema, strict versus narrowly normalized parsing, and supervised fine-tuning (SFT) under that interface. At a fixed Base checkpoint, identical C2 observations, and identical validation IDs, state-only output recognizes 15/15 failure windows while phase/state/failure-mode output recognizes 0/15 after the same outer-fence normalization. On an internally exposed 54-window Tier-B diagnostic, SFT changes strict JSON validity from 0/54 to 54/54 but state-only failure recall from 18/18 to 1/18 or 7/18; Base's perfect recall also incurs 18/18 nominal false alarms. The improvement verdict therefore depends on the evaluation axis. We propose a minimal reporting checklist, not a new detector or a claim of independent replication.
\end{abstract}
\keywords{evaluation substrate, robot execution monitoring, output contracts, reporting}

\section{Introduction}
An execution critic may look better because it obeys a JSON contract, yet worse because it misses failures. Conversely, a critic that recognizes every failure may merely raise an alarm on almost every frame. Calling either one ``improved'' depends on the output and evaluation substrate beneath the reported score. We examine this non-policy design choice rather than propose a new robot policy or a stronger failure detector.

We use a precision-assembly failure critic as a small model organism for evaluation-substrate effects. REBOOT supplies bimanual trajectories with phase, failure, and recovery annotations~\citep{reboot2026}; Qwen2.5-VL-3B supplies the critic family~\citep{qwen2025}. Runtime monitors have studied consistency/progress cues and predictive representations~\citep{sentinel2025,robomonitor2026}, while FailBench examines VLM judgments of robot success~\citep{failbench2026}. Our narrower question is how a critic's measured failure readout depends on the interface through which it is asked and scored.

We make four contributions: (i) decompose interface compliance from semantic failure awareness; (ii) show fixed-checkpoint sensitivity to a state-only versus phase/state/failure-mode output contract on identical validation observations; (iii) diagnose SFT under a frozen Tier-B protocol across validity, state Macro-F1, failure recall, false alarms, and class distribution; and (iv) propose a compact reporting checklist. These controls show \emph{output-formulation sensitivity}, not which internal representation or task component caused it.

\section{Study design: the evaluation substrate}
\paragraph{Data and splits.}
The locally audited REBOOT sample contains 60 episodes; seven with annotation/frame inconsistencies are quarantined, leaving 53 usable. The C2 input contains two RGB cameras and four past-only timestamps over the preceding two seconds, never beyond the anchor frame. Development validation has five episodes and 43 windows. The final sparse-visual refit uses six frozen Tier-B episodes and 54 windows, 18 per state. These six episodes are disjoint from the \emph{final refit's} fit and validation data, but all appeared in an earlier method-development training pool. The exposure ledger therefore labels Tier B \emph{internal evidence}; no episode in the local 60-episode same-task sample is completely untouched.

\paragraph{Three substrate layers.}
First, the output contract requests either \texttt{state} alone or \texttt{phase}, \texttt{state}, and \texttt{failure\_mode}. Second, strict interface scoring requires a bare JSON object with the exact keys and labels; the separately reported semantic diagnostic strips whitespace and at most one complete outer unlabeled or lowercase-\texttt{json} fence, with no JSON repair or label remapping. Third, state-only SFT is compared with Base under the same frozen Tier-B windows, with three training seeds. We report validity, semantic state Macro-F1, failure precision/recall, nominal-window false alarms (N-FA), and predicted-class counts. N-FA is not onset-relative early warning. Paired intervals resample whole episodes using identical draws for both models, never individual correlated windows.

\section{Fixed-checkpoint interface sensitivity}
The strongest interface control compares two \emph{Base} runs before SFT. Both use the same checkpoint, C2 images, four frames, decoding budget and seed, and the same ordered 43 validation IDs and references; the recorded configurations differ only in \texttt{task\_schema}. With state-only output, semantic failure recall is 15/15; requesting phase/state/failure-mode output yields 0/15. All full-schema responses parse after the narrow outer-fence normalization, so its zero recall is not merely a parse failure. An apparently secondary output contract therefore changes the returned failure-state readout before fine-tuning. This comparison implicates the output formulation, but does not isolate instruction length, field coupling, or an internal mechanism. The state-only Base also over-alarms on nominal windows and misses recovery; it is not an actionable monitor.

\section{Tier-B diagnostic: the verdict depends on the axis}
Table~\ref{tab:final} comes from six receipt-verified prediction files on identical frozen IDs. Under \emph{strict JSON validity}, state-only Base is 0/54 and every SFT seed is 54/54: training looks dramatically better. Under semantic state Macro-F1, some SFT seeds improve on Base. Under \emph{failure recall}, Base is 18/18 while the SFT seeds reach only 1/18, 7/18, and 7/18: failure sensitivity looks worse. Yet Base predicts failure in 53/54 responses and falsely alarms on all 18 nominal windows. Its perfect recall is a degenerate high-alarm operating point, not strong monitoring. The direction of the qualitative improvement verdict changes with the evaluation axis; no single number establishes that SFT either improved or degraded the critic overall.

\textbf{Minimal reporting checklist for robot execution critics}
\begin{enumerate}
\item Past-observation boundary and camera/input configuration.
\item Output schema and parser/normalization rules.
\item Interface-validity rate, semantic state metrics, and failure precision/recall.
\item Nominal false-alarm rate and predicted-class distribution.
\item Episode-level split and prior-exposure status.
\end{enumerate}
Our diagnostics motivate this proposed checklist; it is not a universal standard.
\end{minipage}}

\section{Implications and future tests}
The fixed-Base contrast establishes output-formulation sensitivity, but does not identify which added field or interaction drives it. A pre-specified $2\times2$ interface study would cross the inclusion of \texttt{phase} and \texttt{failure\_mode} while always requesting \texttt{state}: state only, state+phase, state+failure mode, and state+phase+failure mode. It would hold checkpoint, observations, ordered sample IDs, decoding, a common state parser/normalization rule, and semantic evaluation fixed; exact-schema validity would be reported separately. This would distinguish field and interaction effects from interface compliance, not assume a mechanism in advance.

A second test would freeze the reporting protocol, analysis code, and episode-level split before inspecting another REBOOT task, then ask whether the direction and magnitude of interface sensitivity recur. Both follow-ups treat the interface as an experimental factor rather than an implementation constant. Neither experiment has been run.

\section{Limitations and conclusion}
This is one critic family on one task, with only six internally exposed final episodes; it is a controlled diagnostic model organism, not an independent or cross-task replication. Annotation-defined failure intervals are not independent human judgments of visual observability. The schema contrast changes the requested fields and associated parser together, so it does not identify a unique prompt component or internal representation mechanism. No production-safety or recovery-policy improvement follows. A planned V2 reward intervention failed its pre-test validation gate, so no V2 GRPO or GSPO was run; historical V1 RL runs are not controlled causal evidence.

The lesson is methodological: making interface and evaluator choices explicit can change the strength and even the direction of the \emph{qualitative} claim about a robot critic. Report the substrate before attributing a measured gain to post-training.
